# AI_investing V3.8.2 P2.2 Portfolio Risk Cutover Report

## Objective

P2.2 connects the canonical production risk-input artifact to the active
portfolio allocator. It admits only candidates whose production eligibility and
risk readiness both pass, while preserving the V3.8.1 allocation caps and
fail-closed behavior.

## Before Cutover

`portfolio_risk.py` reread `production_candidates.csv`. Even when it found a
valid BUY/ELIGIBLE candidate, it returned the temporary guard
`PRODUCTION_RISK_INPUTS_NOT_READY_NO_ACTION`. Production risk evidence could not
reach allocation.

## After Cutover

The formal input is now `results/portfolio_risk_inputs.csv`, loaded only through
`portfolio_risk_calculator.load_production_risk_inputs()`. The temporary guard
has been replaced with validation of the complete candidate, metadata, price,
and risk contract. Valid risk-ready rows proceed to the existing allocator.

`run_all.py` now runs the minimum required sequence:

1. production candidate build;
2. production risk input build;
3. model portfolio.

## Authority Boundary

- Production Candidate remains authority for FinalScore, TradeSignal,
  Eligibility, PortfolioEligible, and candidate ranking context.
- Production Risk Inputs provide point-in-time market risk evidence,
  RiskStatus, RiskReadyForPortfolio, and safe price context.
- Portfolio Risk filters and allocates; it does not reconstruct candidate or
  risk evidence.
- Legacy backtest remains RESEARCH_ONLY and is never a fallback.

## Input Validation

Required metadata:

- RunId
- AsOfDate
- UniverseVersion
- ScoreModelVersion
- RiskModelVersion

Required candidate fields:

- Ticker
- CandidateRank
- FinalScore
- TradeSignal
- Eligibility
- PortfolioEligible

Required risk and price fields:

- MaxDrawdown
- SharpeRatio
- RiskLevel
- RiskWeightMultiplier
- RiskStatus
- RiskReadyForPortfolio
- LatestClose
- LatestCloseAsOf

Missing schema or incompatible metadata returns
`PRODUCTION_RISK_INPUTS_INCOMPATIBLE_NO_ACTION`. A missing artifact returns
`PRODUCTION_RISK_INPUTS_MISSING_NO_ACTION`. There is no fallback.

Allocation admission requires all of:

- PortfolioEligible true
- RiskReadyForPortfolio true
- RiskStatus `RISK_READY`
- finite FinalScore, MaxDrawdown, and SharpeRatio
- finite positive RiskWeightMultiplier
- RiskLevel Low, Medium, or High

Unknown and invalid rows are excluded before MAX_HOLDINGS selection.

## Metadata Enforcement

RunId, AsOfDate, UniverseVersion, ScoreModelVersion, and RiskModelVersion must be
present and single-valued. UniverseVersion must equal
`config.PRIMARY_UNIVERSE_VERSION`; RiskModelVersion must equal
`risk-model-v3.8.2-p2`. Ready rows must have a valid
`LatestCloseAsOf <= AsOfDate`. Duplicate tickers are rejected. All five metadata
fields propagate unchanged into every allocated row.

## Score Field Migration

Production ranking is now:

1. FinalScore descending;
2. CandidateRank ascending;
3. Ticker ascending.

CandidateRank is a tie-break after the explicit FinalScore authority. A
BacktestScore output column remains only as `FinalScore` compatibility output
for existing downstream display/schema consumers; it is not a ranking input and
is not required in the production risk-input artifact.

## AverageReturn / WinRate Cleanup

AverageReturn and WinRate have been removed from the active allocator's required
input contract. They may remain nullable in a risk artifact but are neither
validated nor used, and no values are manufactured for allocation.

## Allocation Policy Confirmation

The P1 policy is unchanged:

- MAX_HOLDINGS: 10
- MAX_TOTAL_EXPOSURE: 80%
- single-position cap: 10%
- redistribution after an individual cap: none
- unused exposure: retained as cash

The processing order remains validation, readiness filtering, deterministic
ranking, selection, multiplier normalization, single-position capping, and
invariant checks.

## Partial / All-Unavailable Semantics

- Partial readiness: allocate only ready rows; excluded eligible rows are
  recorded in the result attribute `ExcludedRiskCandidates` with ticker and
  RiskStatus.
- Eligible but none ready: `NO_RISK_READY_CANDIDATES` with stable empty schema.
- No PortfolioEligible rows: `NO_QUALIFIED_CANDIDATES`, a normal no-action state.
- No positive usable multipliers after selection: `NO_SIZABLE_POSITIONS`.
- Metadata incompatibility: distinct incompatible-input no-action status, not an
  ordinary no-candidate result.

## No-Legacy-Fallback Proof

The active allocator imports only the canonical production-risk reader and risk
model identity. Its source contains no backtest-qualified filename, backtest
output constant, forward-return reader, or try-production-then-backtest branch.
Tests inspect this boundary. Production allocation works from an in-memory risk
artifact without any backtest artifact present.
