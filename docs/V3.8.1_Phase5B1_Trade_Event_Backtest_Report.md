# AI_investing V3.8.1 Phase 5B-1 Trade Event Backtest Report

Report date: 2026-08-12

## 1. Methodology

Phase 5A records a production screening state for every eligible date-symbol
observation. Consecutive BUY rows therefore describe a continuing BUY state,
not necessarily independent economic decisions.

Phase 5B-1 consumes `results/production_backtest_signals.csv` without
recalculating scores. It converts the repeated state observations into entry
events and uses canonical OHLCV only to resolve entry/exit dates, Close prices,
and post-entry excursions.

Observation-based unit:

```text
BUY on day t = one observation
BUY on day t+1 = another observation
```

Entry-based unit:

```text
non-BUY → BUY = one entry event
continuing BUY = no new entry
```

## 2. Entry Definition

An entry occurs when the current trading-row state is BUY and the immediately
preceding trading-row state for the same ticker is not BUY.

The Phase 5A file retains BUY and WATCH but omits IGNORE rows. The generator
therefore uses the ticker’s canonical market calendar:

- a BUY on the immediately preceding market row means the state is continuing;
- a preceding WATCH row means WATCH→BUY and creates an entry;
- a gap in Phase 5A rows means the preceding market row was IGNORE and creates
  an entry; and
- the first historical BUY for a ticker creates an entry.

No production signal, score, threshold, or filter is recalculated or modified.

`EntryPrice` is the canonical Close on EntryDate. Exit prices use Close exactly
5, 20, or 60 trading rows later. If that row is beyond available history, its
exit date and return remain explicitly missing.

Maximum favorable/adverse excursion is Close-based over the inclusive path
from entry through 60 trading rows. It is missing unless a complete 60-row
post-entry window exists. Intraday High/Low are not used, so these are
close-to-close excursion measures.

### Risk statistics

- Diagnostic maximum drawdown proxy: -4.49%.
- Average 60D close-based adverse excursion: -10.64% (36 complete windows).

The drawdown proxy groups valid 20D event returns by entry date, converts each
date’s average 20D return to a daily-equivalent return, and compounds those
date-level values. It is not an executable portfolio drawdown.

## 5. Limitations

- **Current-universe survivorship bias:** the historical reconstruction uses
  today’s 19-symbol watchlist.
- **No point-in-time universe:** historical membership changes are unavailable.
- **Overlap reduced, not eliminated:** consecutive BUY days are collapsed, but
  different tickers can overlap and a ticker can re-enter before an earlier
  fixed evaluation horizon ends. The module does not impose a holding/exclusion
  rule because production does not define one.
- **No transaction costs or slippage:** all returns use recorded Close values.
- **No portfolio allocation or capital constraints:** every entry is evaluated
  independently, with no sizing, maximum holdings, or cash competition.
- **No exit policy:** 5D/20D/60D are evaluation horizons, not production sell
  instructions.
- **Excursions are Close-based:** intraday adverse/favorable moves can be larger.
- **Small/concentrated sample:** 53 entries come from seven symbols, with 32
  entries from MU and SNDK alone. Historical averages should not be treated as
  stable expected returns.

## Recommendation

The trade-event model is complete as a research layer and is suitable input for
a separately specified portfolio backtest. That next phase must define holding,
exit, re-entry, concurrency, capital allocation, costs, and point-in-time
universe assumptions explicitly before claiming portfolio performance.

The prudent conclusion is that entry conversion improves the unit of analysis;
it does not establish future profitability.
