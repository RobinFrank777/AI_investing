# V3.8.1 O1.1 Aggregate Order Review Status Report

## Previous Inconsistency

The O1 read-only smoke check produced 5 PASS rows and 5 REVIEW rows, yet `PortfolioReviewFlag` remained PASS because aggregation considered only order count and total value. That contradicted the row-level manual-review requirement.

## Final Row-Level Status Meanings

- `PASS`: current mechanical checks passed; human decision is still required.
- `REVIEW`: an order requires explicit manual attention, including missing fundamentals, high risk, or the single-order review limit.
- `BLOCKED`: an order violates a hard numeric/action/status contract and must not proceed.

## Final Portfolio-Level Aggregation Rule

- Empty: status `NO_ORDERS_TO_REVIEW`; flag `NOT_APPLICABLE` in the in-memory empty-result contract.
- Any BLOCKED row: `PortfolioReviewFlag = BLOCKED`.
- Any REVIEW row and no BLOCKED row: `PortfolioReviewFlag = REVIEW_REQUIRED`.
- All PASS, with at least one order: `PortfolioReviewFlag = PASS`.
- Portfolio count/value warnings also produce `REVIEW_REQUIRED` unless a BLOCKED row takes precedence.

## Severity Ordering

`BLOCKED > REVIEW_REQUIRED > PASS`. `NOT_APPLICABLE` is reserved for empty orders.

## Smoke Check Before / After

Before: PASS 5, REVIEW 5, BLOCKED 0, portfolio flag PASS.
After: PASS 5, REVIEW 5, BLOCKED 0, portfolio flag `REVIEW_REQUIRED`.

The smoke check was read-only. It did not overwrite artifacts or transmit orders.

## Manual Review Boundary

Row PASS and portfolio PASS mean only that current mechanical checks passed. Neither authorizes execution. Every proposal remains subject to a human decision.

## Consumers and Validation

`portfolio_action_report.py` already derives its decision from row severity and correctly reports manual review or blocked orders; no report rewrite was needed. The order-review validator now recognizes the formal aggregate flags and verifies the same severity ordering. Central allowed values are `PASS`, `REVIEW_REQUIRED`, `BLOCKED`, and `NOT_APPLICABLE`.

## Tests

Focused coverage includes empty, all-PASS, PASS+REVIEW, REVIEW-only, PASS+BLOCKED, REVIEW+BLOCKED, all three severities, missing fundamentals, and invalid numeric input.

## Scope Verification

O1.1 changed only aggregate order-review semantics, the directly corresponding allowed-value configuration, validator, tests, and documentation. It did not change position sizing, order drafting, scoring, thresholds, portfolio risk, project version, fundamentals, or Universe membership.
