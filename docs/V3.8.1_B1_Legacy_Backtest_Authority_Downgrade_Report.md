# AI_investing V3.8.1 B1 — Legacy Backtest Authority Downgrade

## Problem

The legacy default portfolio loader read
`results/backtest_qualified_20d.csv`. Because both `run_all.py` and
`run_portfolio.py` invoked that loader, the research artifact could flow through
portfolio allocation, position sizing, and draft-order review while the newer
production candidate chain also existed. This created two competing sources of
authority and allowed a legacy research list to appear actionable.

## New Authority Contract

The sole formal production authority chain is:

`FinalScore → TradeSignal → Production Candidate → Portfolio Risk → Position Sizing → Order Draft → Order Review`

`trade_signal.py` owns signal semantics and
`production_candidate_builder.py` owns candidate creation. The default P1
portfolio entry now reads only `results/production_candidates.csv` through the
production candidate adapter. Backtest output is outside this chain.

## Legacy Backtest Status

`results/backtest_qualified_20d.csv` and its associated backtest pipeline are
`RESEARCH_ONLY`. They may support historical diagnostics, comparisons,
backtest reports, and model investigation. They may not select production
candidates or authorize portfolio allocation, sizing, draft orders, order
review, or execution.

The backtest runner, engine summary, validator, and README now state
`RESEARCH ONLY — NOT PRODUCTION BUY AUTHORITY`. The historical CSV schema was
not expanded.

## Production Dependencies Removed

- `portfolio_risk.py` no longer imports or reads
  `BACKTEST_QUALIFIED_20D_OUTPUT_PATH` in its default entry path.
- `run_all.py` builds the production candidate artifact before invoking the
  portfolio boundary.
- `run_all.py` may still run backtests as an independent research step, but the
  resulting qualified list is not passed to the model portfolio.
- `run_portfolio.py` reaches the same production-only default portfolio entry
  and therefore cannot use a legacy backtest fallback.
- Position sizing, order draft, and order review remain downstream of the
  resulting model portfolio and do not read the legacy backtest artifact.

## Remaining Research Uses

- `run_backtest.py` and the backtest step in `run_all.py` continue to generate
  historical diagnostics.
- `validate_backtest_outputs.py` continues to validate research CSV integrity.
- Backtest score/risk frames may still be injected directly into the P1
  allocator by isolated compatibility and policy tests. This explicit test API
  is not the no-argument production loader.
- Historical artifacts and algorithms are retained unchanged.

## Fail-Safe Contract

The default production portfolio path has no backtest fallback:

- missing production candidates → `PRODUCTION_CANDIDATES_MISSING_NO_ACTION`
- empty/no eligible production candidates → `PRODUCTION_CANDIDATES_EMPTY_NO_ACTION`
- stale production candidates → `PRODUCTION_CANDIDATES_STALE_NO_ACTION`
- incompatible production candidates → `PRODUCTION_CANDIDATES_INCOMPATIBLE_NO_ACTION`
- valid candidates without completed production risk inputs →
  `PRODUCTION_RISK_INPUTS_NOT_READY_NO_ACTION`

B1 intentionally does not force the pending production candidate-to-risk
allocation cutover. Until that downstream contract is ready, the correct safe
result is an empty portfolio and no production orders, never borrowed legacy
metrics.

## Reporting Boundary

Backtest results may be shown only as Research Backtest Result, Historical
Qualified Setup, or Backtest Diagnostic. They must not be labeled Production
BUY, Current Action, or Portfolio Recommendation. Production action reporting
is downstream of the production-only model-portfolio entry and remains subject
to human review. Full cross-artifact reporting consistency is reserved for R1.

## Tests

Focused B1 tests cover the research-only authority marker, absence of a legacy
artifact dependency from the production portfolio source, missing/empty/
incompatible candidates, the risk-not-ready state, no fallback, and retention
of the injected P1 policy-test boundary. Existing production-candidate adapter,
P1, and C1 contract tests are also included in focused regression validation.
