# AI_investing V3.8.1 Phase 5A Backtest Architecture Audit

Audit date: 2026-08-12

## Existing backtest flow

```text
Canonical OHLCV
  ↓ stock_loader.load_stock
Indicators
  ↓ backtest_engine.prepare_backtest_data
Four technical filters
  ↓ Close > MA20; MA20 > MA60; Volume_Ratio > 0.8; DistanceToHigh ≥ 0.95
BUY/WATCH/IGNORE
  ↓ first BUY after non-BUY becomes EntrySignal
Fixed 20-row holding return
  ↓
Legacy backtest summary and qualification
```

The legacy engine does not calculate RawScore, RS_Score, NearHighScore, or
FinalScore. Its WATCH state means required indicator data exists. Consequently,
it evaluates a different signal policy from production.

## Target production-faithful flow

```text
Historical canonical OHLCV
  ↓
Indicators using rows at or before each signal date
  ↓
TrendScore + MomentumScore + MACD/return contributions + VolumeScore + RiskScore
  ↓
Current RawScore formula
  ↓ date-by-date cross-sectional scoring
RS_Score + NearHighScore
  ↓
Current FinalScore formula
  ↓ trade_signal.generate_signals
Production BUY/WATCH/IGNORE policy
  ↓
5D / 20D / 60D forward-return evaluation
```

## Implementation boundary

`production_backtest.py` is an independent diagnostic module. It does not
replace or modify `backtest_engine.py`, `score.py`, `trade_signal.py`, the
thresholds, or any portfolio/risk rule.

The module uses the Phase 4 historical score builder, which calls:

- canonical `stock_loader.load_stock()` for repository data;
- production `indicators.calculate_indicators()`;
- production `score.calculate_rank_score_diagnostics()`;
- production `score.calculate_final_score()` for each historical date
  cross-section; and
- production `trade_signal.generate_signals()` without duplicating its policy.

## Look-ahead controls

At signal date `t`, all score inputs are derived from row `t` and earlier rows:

- rolling indicators use backward-looking pandas windows/EMA calculations;
- trailing returns use Close at `t`, `t-19`, and `t-59` rows;
- High60/High252 and VolumeMA20 use rolling windows ending at `t`;
- RS_Score uses only same-date scores/60-day returns across the configured
  symbols; and
- FinalScore and TradeSignal are calculated before forward returns are read.

Future Close values are used only after the signal is fixed to calculate
`Close[t+5]/Close[t]-1`, `Close[t+20]/Close[t]-1`, and
`Close[t+60]/Close[t]-1`. Unavailable horizons remain missing and are not
filled.

Automated tests mutate all prices after a cutoff and verify that scores and
signals at or before the cutoff are identical. A separate test verifies that
the diagnostic signal classification exactly matches
`trade_signal.generate_signals()`.

## Universe qualification

The reconstruction uses the current 19-symbol watchlist historically because
the repository has no point-in-time membership history for this production
universe. This avoids future price leakage but does not eliminate survivorship
or selection bias from knowing today’s universe. Results therefore measure
historical behavior of the current universe, not a fully point-in-time
investable universe.

## Output interpretation

`results/production_backtest_signals.csv` records every historical BUY and WATCH
date-symbol observation. Consecutive BUY days are separate observations; the
module does not invent an entry-transition or portfolio-holding rule because
production ranking has neither. Summary returns overlap and are research
diagnostics, not executable portfolio performance.
