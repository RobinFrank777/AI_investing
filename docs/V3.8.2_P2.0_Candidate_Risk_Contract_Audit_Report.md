# AI_investing V3.8.2 P2.0 Candidate-to-Risk Contract Audit

Audit baseline: local `main` at `df1a31c` (`v3.8.1` release commit)

## 1. Executive Summary

The production candidate authority is correctly detached from legacy backtest
authority, but an eligible BUY cannot reach allocation. The active consumer
validates `production_candidates.csv`, detects `PortfolioEligible`, and then
unconditionally returns `PRODUCTION_RISK_INPUTS_NOT_READY_NO_ACTION`.

The repository already contains a separate point-in-time candidate adapter and
risk calculator. They are not orchestrated by `run_all.py`, and their risk
schema does not satisfy the active allocator's legacy-shaped
`BacktestScore/MaxDrawdown/SharpeRatio` contract. P2.1 should adapt this existing
point-in-time foundation rather than revive a backtest artifact or create a
second risk framework.

## 2. Production Candidate Contract

### Artifact and authority

- Path: `results/production_candidates.csv`
- Producer: `production_candidate_builder.run_production_candidate_builder()`
- Upstream: `results/stock_rank.csv`, produced by the production ranking path
- Active reader: `portfolio_risk.load_qualified_candidates()` through
  `portfolio_candidate_adapter.load_production_candidates()`
- Additional independent reader: `portfolio_candidate_adapter.py`
- Current rows: 148
- Current PortfolioEligible/eligible BUY rows: 0
- Current signals: IGNORE 142, WATCH 6, BUY 0

The fixed production artifact schema is:

1. Ticker
2. RunId
3. AsOfDate
4. CandidateRank
5. Eligibility
6. FinalScore
7. TradeSignal
8. RS_Score
9. NearHighScore
10. Confidence
11. ScoreModelVersion
12. UniverseVersion

`LatestClose` and `PortfolioEligible` are not fields in the production candidate
artifact. `PortfolioEligible` is derived by the adapter; `LatestClose` is read
later from the latest market CSV by position sizing, which is a replay/cutover
gap because it is not explicitly bound to candidate AsOfDate.

The builder rejects missing schema, incompatible UniverseVersion, blank or
duplicate tickers, mixed/blank ScoreModelVersion, invalid TradeSignal,
non-finite scores, mixed/invalid market dates, future dates, and dates more than
five calendar days stale. Empty input produces a stable header-only artifact.
RunId is deterministic from canonicalized input plus AsOfDate.

### Eligibility

The sole candidate authority is the production TradeSignal chain:

- FinalScore >= 75
- Volume_Ratio > 0.8
- DistanceToHigh >= 0.95
- Close > MA20
- MA20 > MA60

Only `TradeSignal == BUY` is mapped to `Eligibility == ELIGIBLE`. The portfolio
adapter then requires both BUY and ELIGIBLE before setting PortfolioEligible.
WATCH and IGNORE cannot be promoted. Invalid/missing numeric or metadata values
fail validation rather than become eligible.

There is no hidden backtest dependency, watchlist fallback, legacy ranking
fallback, or qualified-column promotion in this chain.

## 3. Portfolio Risk Input Contract

### Active allocator contract

The injected allocation path in `portfolio_risk.build_model_portfolio()`
currently requires:

- Ticker: true production requirement
- BacktestScore: used as finite eligibility and primary ranking field; legacy
  name and legacy semantics
- AverageReturn: required but not used in allocation; legacy compatibility
- WinRate: required but not used in allocation; legacy compatibility
- MaxDrawdown: finite input to RiskLevel
- SharpeRatio: finite input to RiskLevel

It derives:

- RiskLevel
- RiskReady
- RiskWeightMultiplier
- TargetWeight / TargetWeightPercent
- PortfolioRole / PortfolioStatus

Risk thresholds are unchanged:

- Low: MaxDrawdown >= -0.10 and SharpeRatio >= 2
- Medium: MaxDrawdown >= -0.25 and SharpeRatio >= 1
- High: all other finite pairs
- Unknown: missing or non-finite inputs

Multipliers are Low 1.00, Medium 0.80, High 0.50, Unknown 0.00.
Risk-ready rows are filtered before MAX_HOLDINGS selection. Allocation remains
bounded by 10 holdings, 10% per position, and 80% total exposure.

`AverageReturn` and `WinRate` are display/compatibility fields, not true risk
allocation inputs. Tests still construct the full legacy-shaped frame directly;
they validate allocation safety but not the real candidate-to-risk join.

### Existing independent risk contract

`portfolio_risk_calculator.py` reads
`results/validated_portfolio_candidates.csv` and writes
`results/portfolio_risk_inputs.csv`. It requires a matching pre-trade portfolio
snapshot and emits point-in-time volatility, current trailing drawdown, ATR,
liquidity, status, and provenance. It deliberately excludes BacktestScore,
MaxDrawdown, SharpeRatio, RiskLevel, and multiplier fields, so the active
allocator cannot consume it.

## 4. Exact Blocker

Definition: `portfolio_risk.PRODUCTION_RISK_INPUTS_NOT_READY` equals
`PRODUCTION_RISK_INPUTS_NOT_READY_NO_ACTION`.

Call path:

`run_all.py` → `print_model_portfolio()` → `build_model_portfolio()` →
`load_qualified_candidates()` → production candidate loader/adapter.

Trigger:

1. production candidate artifact exists and validates;
2. artifact is within the five-day freshness limit;
3. at least one row has BUY + ELIGIBLE and therefore PortfolioEligible=True.

At that point the function unconditionally returns an empty portfolio with the
guard status. No metric fields are inspected because no production risk-ready
frame is built. Downstream sizing, order draft, review, and reports receive a
safe no-action state.

This is a temporary cutover guard, not allocation policy. It can be removed only
after a same-run, point-in-time, metadata-compatible risk artifact provides the
eligible candidate score plus finite MaxDrawdown and SharpeRatio (or an approved
replacement risk-level contract). There is no default-path bypass and no legacy
fallback. Direct DataFrame injection remains available only for unit/contract
tests.

## 5. Historical Risk Metric Sources

| Source | Classification | Finding |
|---|---|---|
| `backtest_engine.py` and backtest CSVs | RESEARCH_ONLY | MaxDrawdown and SharpeRatio are based on completed forward trades. They must not become production candidate or risk authority. |
| `production_backtest.py` | RESEARCH_ONLY diagnostic | Uses forward returns and cohort summaries; unsuitable for decision-time candidate risk. |
| `risk_engine.py` | Reusable formula reference only | Computes close-series annualized volatility, maximum drawdown, and zero-risk-free Sharpe, but reads the full file, has no AsOf cutoff, and has an insufficient minimum-observation contract. Not directly production-safe. |
| `universe_risk_runner.py` | Research-only artifact | Applies `risk_engine` across Universe150 and writes raw research metrics. It is not RunId/AsOf-bound. |
| `portfolio_risk_calculator.py` | Reusable production-oriented foundation | Correctly truncates Date <= candidate AsOfDate, requires 60 observations, checks staleness, and emits RiskModelVersion/status. Its metric/schema and snapshot dependency do not yet satisfy active allocation. |
| `risk_analysis.py`, `stock_personality.py` | Legacy exploratory scripts | Ad-hoc full-history calculations and sign conventions; not suitable as production readers. |

For P2.1, reuse the date truncation, validation, status, and metadata approach of
`portfolio_risk_calculator.py`. Reimplement only the approved allocator metrics
inside that point-in-time window; do not read legacy backtest output.

## 6. Point-in-Time Contract

Every risk observation must satisfy `Date <= Candidate.AsOfDate`. The window is
selected only after that cutoff. Future rows, forward returns, completed-trade
outcomes, and latest-file shortcuts are forbidden.

Current helper status:

- `portfolio_risk_calculator._calculate_market_risk`: point-in-time safe and
  covered by future-mutation/append tests.
- `risk_engine.calculate_risk_metrics`: not point-in-time safe when called on a
  normal full current CSV.
- `backtest_engine` metrics: outcome-based research metrics, not decision-time
  risk inputs.
- `position_sizing.get_latest_close`: reads the last file row and is not replay
  bound to Candidate.AsOfDate; P2.1 must either propagate an AsOf-bound price or
  explicitly validate that the loaded close date equals the production AsOfDate.

Recommended approved window for the minimal extension is the existing trailing
60 completed rows, with 59 daily close returns, because this preserves the
already-tested risk calculator's minimum-history and staleness contract. Define:

- MaxDrawdown = minimum of `Close / cumulative_max(Close) - 1` in that window;
  sign is zero or negative.
- SharpeRatio = mean daily return / sample standard deviation × sqrt(252), with
  risk-free rate 0 under the existing repository convention.
- Zero volatility, insufficient observations, NaN, or Inf = not risk ready.

If governance instead selects 252 rows, that is a policy/calibration decision
and must be explicit before implementation; P2.0 does not choose a new threshold
or silently change existing risk classification.

## 7. Metadata Contract

- RunId: copied exactly from the production candidate run; all risk rows and the
  consumer must match it.
- AsOfDate: copied exactly from candidate and used as the OHLC cutoff.
- UniverseVersion: copied from production candidate and checked against
  `config.PRIMARY_UNIVERSE_VERSION`.
- ScoreModelVersion: inherited unchanged from candidate.
- RiskModelVersion: one canonical constant in the risk builder, recommended
  `risk-model-v3.8.2-p2` after approval.

Current gaps: `portfolio_candidate_adapter.py` drops UniverseVersion, and
`portfolio_risk_calculator.py` neither consumes nor emits it. The current risk
version is `portfolio-risk-v3.8.1-r1`; P2.1 should replace/update this single
authority rather than introduce a competing constant.

Artifact-level mixed RunId, AsOfDate, UniverseVersion, ScoreModelVersion, or
RiskModelVersion must fail closed. Candidate/risk key mismatches must never use a
nearest/latest row.

## 8. Missing Risk Data Contract

Recommended P2.1 behavior:

- Partial ready set: allocate only PortfolioEligible rows whose risk status is
  READY/PASS and whose metadata matches. Preserve failed rows and reasons in the
  risk artifact; do not fill unused slots from non-BUY names.
- All unavailable: empty portfolio with `NO_RISK_READY_CANDIDATES`.
- Invalid numeric, invalid OHLC, zero volatility, metadata mismatch, or corrupt
  calculation: candidate BLOCKED/FAILED and excluded.
- Insufficient or stale history: candidate PENDING/FAILED and excluded.
- Missing metric: never classify Low and never fill with zero.
- No legacy qualified-list fallback and no fabricated metrics.

UNKNOWN is not safe. A partial continuation must still apply the existing
holding and exposure caps to the ready subset only.

## 9. Score Field Naming

Current allocator field: BacktestScore.

Semantic issue: the field name and current injected-test values represent the
old backtest ranking authority. Production selection/ranking authority is
FinalScore and CandidateRank. Continuing to rank on a genuine backtest score
would violate B1.

Recommendation: **ALIAS, then MIGRATE/DEPRECATE**.

For the minimal cutover, the portfolio frame may expose
`BacktestScore = FinalScore` only as a clearly documented downstream
compatibility alias while preserving canonical FinalScore and CandidateRank.
The allocator must sort by FinalScore (then CandidateRank/Ticker), not a legacy
backtest artifact. A later compatibility cleanup should migrate combined
scoring, sizing, validators, and reports to a correctly named production score
field and deprecate BacktestScore. Do not KEEP its legacy semantics.

`AverageReturn` and `WinRate` should not be fabricated. Remove them from true
required allocation inputs; retain nullable compatibility output only if a
downstream schema requires it during the controlled migration.

## 10. Artifact Boundary

Use the already-existing path `results/portfolio_risk_inputs.csv`; do not create
another `production_risk_inputs.csv` with overlapping authority.

Recommended P2.1 schema groups:

- Candidate identity: Ticker, RunId, AsOfDate, CandidateRank, FinalScore,
  TradeSignal, PortfolioEligible
- Version identity: UniverseVersion, ScoreModelVersion, RiskModelVersion
- Observation identity: ObservationEndDate, RiskObservationCount,
  CalculationTimestamp
- Allocation metrics: LatestCloseAsOf, MaxDrawdown, SharpeRatio
- Existing optional diagnostics: Volatility20D, Volatility60D, TrailingDrawdown,
  ATR14, AverageVolume20D, AverageDollarVolume20D, LiquidityCoverage
- State: RiskStatus, RiskValidationStatus, RiskValidationReason

Producer: the existing candidate adapter plus extended
`portfolio_risk_calculator.py`, orchestrated immediately after production
candidate creation.

Reader: `portfolio_risk.py`, using an exact metadata/key match and only
READY/PASS eligible rows.

The existing `validated_portfolio_candidates.csv` may remain the narrow adapter
boundary, but it must preserve UniverseVersion if retained.

## 12. Test Gaps

Existing coverage includes candidate BUY+ELIGIBLE derivation, empty states,
invalid/mixed candidate data, current risk calculator future-data isolation,
insufficient history, invalid numeric market data, snapshot conflicts,
deterministic RiskModelVersion, allocation caps, partial valid injected risk
rows, all-risk-unavailable, no-action regression, order/capital invariants, and
no legacy fallback.

Missing integration/contract tests:

- real production candidate plus calculated MaxDrawdown/SharpeRatio into active
  portfolio allocation;
- partial READY/PENDING/BLOCKED candidate sets through the default reader;
- all eligible candidates risk unavailable through the real artifact path;
- UniverseVersion preservation and mismatch rejection in adapter/risk consumer;
- RiskModelVersion mismatch/mixed rejection by portfolio consumer;
- exact candidate/risk RunId and AsOfDate join failures;
- latest close bound to replay AsOfDate;
- BUY-day replays for one and multiple candidates;
- replay with data appended/mutated after AsOfDate through the full chain;
- no-action regression after orchestration changes;
- proof that BacktestScore is compatibility alias only and no backtest CSV is
  read.

## 13. P2.1 Minimal Design

1. Preserve UniverseVersion through `portfolio_candidate_adapter.py` and require
   single compatible candidate metadata.
2. Extend the existing point-in-time risk calculator rather than creating a new
   framework. Keep Date <= AsOfDate, the existing history minimum, staleness,
   and row-level READY/PENDING/BLOCKED states.
3. Add finite point-in-time MaxDrawdown and SharpeRatio plus LatestCloseAsOf to
   the risk artifact; keep existing optional diagnostics.
4. Carry CandidateRank and FinalScore into the risk artifact without allowing
   risk computation to alter eligibility.
5. Define one canonical V3.8.2 RiskModelVersion and enforce RunId, AsOfDate,
   UniverseVersion, ScoreModelVersion, and RiskModelVersion consistency.
6. Add the adapter/risk builder to `run_all.py` immediately after production
   candidate creation and validate both artifacts before portfolio construction.
7. Change the default `portfolio_risk.py` reader to consume
   `portfolio_risk_inputs.csv`, filter PortfolioEligible + READY/PASS rows, rank
   by FinalScore/CandidateRank, and apply the unchanged RiskLevel, multiplier,
   and exposure policies.
8. If downstream compatibility requires BacktestScore, emit it only as an alias
   of FinalScore and test that no backtest artifact is read. Do not fabricate
   AverageReturn or WinRate.
9. Partial ready continues safely; all unavailable returns
   NO_RISK_READY_CANDIDATES; any artifact-level metadata conflict returns an
   explicit incompatible/no-action state.
10. Propagate metadata and AsOf-bound close through portfolio/sizing so reports
    can verify the same run and replay cannot consume a future price.
11. Add focused unit/integration tests and replay the three prioritized BUY
    dates without overwriting current production artifacts.
