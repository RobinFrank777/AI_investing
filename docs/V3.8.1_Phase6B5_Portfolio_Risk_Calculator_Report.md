# AI_investing V3.8.1 Phase 6B-5 Portfolio Risk Calculator Report

Date: 2026-08-12

Status: independent risk-input implementation only. The active portfolio and
order pipeline is unchanged.

# 1. Purpose

`portfolio_risk_calculator.py` converts validated, production-derived eligible
candidates into a point-in-time risk artifact. It makes current market risk,
liquidity, data sufficiency, and pre-trade portfolio exposure explicit before a
future portfolio-consumer migration.

The calculator does not determine whether a stock is attractive. It neither
recalculates nor emits FinalScore, TradeSignal, or PortfolioEligible. A BUY is
not allowed to bypass missing risk information.

# 2. Implemented Risk Contract

Input candidate artifact:

`results/validated_portfolio_candidates.csv`

Output artifact:

`results/portfolio_risk_inputs.csv`

Row grain is one PortfolioEligible ticker for a single candidate RunId,
AsOfDate, ScoreModelVersion, portfolio snapshot, and RiskModelVersion.

| Field | Source and definition | Lookback | Missing/invalid behavior |
|---|---|---:|---|
| Ticker, RunId, AsOfDate, ScoreModelVersion | Exact validated-candidate provenance | N/A | Artifact rejected for missing/mixed identity |
| RiskModelVersion | Calculator constant | N/A | Always required |
| PortfolioSnapshotId, PortfolioAsOfDate | Explicit pre-trade snapshot | N/A | Row PENDING/FAILED when absent; artifact rejected when conflicting/future |
| CalculationTimestamp | UTC calculator execution time | N/A | Always emitted for a non-empty assessment |
| ObservationEndDate | Latest canonical OHLCV date actually used | <= AsOfDate | Never future; stale data is PENDING/FAILED |
| RiskObservationCount | Number of trailing rows used | 60 rows | Fewer than 60 is PENDING/FAILED |
| Volatility20D | Sample standard deviation of daily Close returns, annualized by sqrt(252) | Last 20 returns | Non-finite result is BLOCKED/FAILED |
| Volatility60D | Sample standard deviation of available daily Close returns in the 60-row window, annualized by sqrt(252) | 60 price rows / 59 returns | Non-finite result is BLOCKED/FAILED |
| TrailingDrawdown | Latest Close divided by the known trailing peak Close, minus one | 60 rows | Non-finite result is BLOCKED/FAILED |
| ATR14 | Mean true range using High, Low, and previous Close | 14 rows | Non-finite result is BLOCKED/FAILED |
| AverageVolume20D | Mean canonical Volume | 20 rows | Non-finite result is BLOCKED/FAILED |
| AverageDollarVolume20D | Mean Close multiplied by Volume | 20 rows | Non-finite result is BLOCKED/FAILED |
| LiquidityCoverage | Fraction of the 20 rows with both Close and Volume | 20 rows | Required and finite |
| CurrentPortfolioWeight | Explicit pre-trade snapshot value in [0, 1] | N/A | Missing is PENDING/FAILED; invalid is rejected |

The approved optional fields Volatility60D and ATR14 are included because the
same required 60-row canonical history supports them without adding a new
factor. Sector exposure, portfolio correlation, spread proxy, proposed slot
concentration, fundamental risk, RiskLevel, and risk multipliers remain absent.

Output status semantics:

- `RiskStatus=READY` and `RiskValidationStatus=PASS`: required inputs were
  present, current, finite, and point-in-time valid.
- `RiskStatus=PENDING` and `RiskValidationStatus=FAILED`: required history or
  portfolio snapshot is unavailable/stale; no risk value is invented.
- `RiskStatus=BLOCKED` and `RiskValidationStatus=FAILED`: calculation data is
  invalid or calculation failed.

# 3. Point-in-Time Data Rules

For candidate date D, the calculator first truncates canonical OHLCV to
`Date <= D`, sorts by date, and then selects its trailing window. Appended or
mutated rows after D cannot enter any calculation. `ObservationEndDate` records
the last row used and must not exceed D.

The market source is the canonical `stock_loader.load_stock` path. Tests can
inject an equivalent in-memory OHLCV frame to prove date isolation without
altering stored market data. There is no backward fill, forward fill, forward
return, completed-trade outcome, or future universe input.

Market data older than five calendar days relative to AsOfDate is treated as
stale. The portfolio snapshot must match the candidate RunId and AsOfDate, and
its PortfolioAsOfDate cannot exceed candidate AsOfDate.

# 4. RiskModelVersion

The deterministic identifier is:

`portfolio-risk-v3.8.1-r1`

It is distinct from ScoreModelVersion and has no effect on scoring, signals,
eligibility, portfolio allocation, or orders.

# 5. Fail-Closed Behavior

The whole input artifact is rejected for duplicate normalized tickers, mixed
RunId, mixed AsOfDate, mixed ScoreModelVersion, missing identity, non-finite
FinalScore, or an invalid eligibility promotion.

An eligible row cannot PASS when its required market history or portfolio
snapshot is missing, stale, non-finite, invalid, or conflicting. Values are
left explicitly missing on failed rows rather than replaced with zero or a
guessed RiskLevel.

Zero PortfolioEligible candidates is a valid no-action state. The calculator
emits a header-only artifact with the stable schema, zero rows, and zero PASS
results.

# 7. Leakage Validation

Automated tests confirm:

1. Dramatic mutation of every OHLCV row after D leaves the D result identical.
2. Appending future rows leaves the D result identical.
3. The successful fixture records ObservationEndDate equal to D.
4. A future-dated portfolio snapshot is rejected.
5. Insufficient historical coverage is fail-closed.

# 9. Architecture Boundary Confirmation

The calculator does not recalculate FinalScore or TradeSignal and cannot
promote PortfolioEligible. It does not output or consume BacktestScore, legacy
trade SharpeRatio, forward-trade MaxDrawdown, future returns, or fabricated
RiskLevel.

No existing scoring, candidate adapter, portfolio construction, position
sizing, order, or daily reporting module was modified. In particular,
`portfolio_risk.py` has NOT been migrated in this phase.

# 10. Remaining Migration Work
