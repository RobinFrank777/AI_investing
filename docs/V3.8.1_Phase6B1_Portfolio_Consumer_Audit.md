# 2. Candidate Input Dependency

## Immediate input contract

| Item | Current value |
|---|---|
| File | `results/backtest_qualified_20d.csv` |
| Path definition | `config.BACKTEST_QUALIFIED_20D_OUTPUT_PATH` |
| Loader | `portfolio_risk.load_qualified_candidates()` |
| Loader behavior | `pd.read_csv()`, then descending `BacktestScore` sort |

| Selection | First `MAX_HOLDINGS` rows before RiskLevel/multiplier assignment |
| Output | `results/model_portfolio.csv` |

The loader performs no schema, freshness, finite-value, ticker-normalization,
duplicate, or qualification validation. It assumes the legacy backtest output
has already enforced qualification.

## Expected legacy schema

The immediate builder directly consumes:

- `Ticker`;
- `BacktestScore` for ordering;
- `MaxDrawdown` and `SharpeRatio` for RiskLevel.

The model-portfolio validator and display additionally require:

- `AverageReturn`;
- `WinRate`; and
- generated `RiskLevel`, `RiskWeightMultiplier`, `TargetWeight`,
  `TargetWeightPercent`, and `PortfolioRole`.

Other legacy input fields flow through the portfolio artifact even when the
builder does not calculate with them.

dependency.

## Persistent downstream legacy dependencies

- `validate_portfolio_outputs.py` requires BacktestScore, AverageReturn,
  WinRate, MaxDrawdown, and SharpeRatio.
- `combined_scoring.py` assigns BacktestScore a 70% weight.
- `position_sizing.py` converts BacktestScore and uses it as the fallback when
  CombinedScore is missing.
- Order draft/review schemas and their validators require BacktestScore.
- `portfolio_action_report.py` displays BacktestScore.
- Daily decision reporting embeds this legacy-derived action report.

Changing only `portfolio_risk.load_qualified_candidates()` would therefore be
insufficient and would produce either schema failures or misleading aliases.

# 5. Safety Boundary Findings

Read-only in-memory probes were used; no artifact was overwritten.

| Boundary | Current behavior | Assessment |
|---|---|---|
| Zero legacy candidates | `build_model_portfolio()` returns an empty frame with generated columns | Locally safe, but downstream is not end-to-end safe |
| All new candidates INELIGIBLE | Not recognized because current loader never reads Eligibility | FAIL: integration could accidentally include them unless filtered before portfolio construction |
| All Unknown risk | Zero multiplier sum produces NaN TargetWeight | FAIL |
| Missing BacktestScore value | Candidate can still receive a positive TargetWeight because weights ignore score after sorting | FAIL; later validator should reject NaN but allocation already occurred |
| Missing BacktestScore column | Sort raises `KeyError` | Fail-fast but unstructured |
| Missing price file | `get_latest_close()` raises `FileNotFoundError` | Fail-fast |
| Missing Close column | Raises `ValueError` | Fail-fast |
| All Close values NaN | Raises `ValueError` after `dropna()` | Fail-fast |
| Infinite or non-positive Close | Not explicitly rejected | FAIL; infinity/negative values can corrupt share calculations |
| NaN portfolio numerics | Some validator paths detect NaN after numeric conversion | PARTIAL; infinity is not rejected and NaN comparisons can evade rules |
| Duplicate tickers | Can consume multiple holding slots and receive weights; portfolio validator detects exact duplicates only after construction | FAIL; normalization-equivalent duplicates are not checked |
| Zero-share sizing | Draft filters rows with `TargetShares <= 0` | Locally safe, but can create empty downstream artifacts |
| Empty position-sizing validation | `check_total_exposure()` uses `AccountValue.iloc[0]` | FAIL with index error |
| Empty draft generation | Produces a stable empty draft schema | PASS locally |
| Empty order-review build | Produces an empty frame with review columns | PASS locally |
| Empty order-review print/validation | Both index `PortfolioReviewFlag.iloc[0]` | FAIL |
| NaN order shares/value | Comparisons are false, so `assign_review_status()` returns PASS and “no issue” | CRITICAL boundary failure |
| Missing fundamentals | Filled with score 0/rating MISSING; CombinedScore may fall back to BacktestScore and order Action remains BUY | FAIL: missing data is not forced to review/block |
| Empty action report | With a correctly shaped empty frame, decision falls through to READY FOR MANUAL CONFIRMATION | FAIL: no orders should have an explicit no-action state |
| Daily decision freshness | Selects latest technical report by filesystem mtime and combines current action text | FAIL: no RunId/AsOfDate compatibility check |

Additional observations:

- Portfolio selection occurs before RiskLevel assignment, so Unknown candidates
  can consume `MAX_HOLDINGS` slots even though their multiplier is zero.
- `.clip(upper=MAX_POSITION_WEIGHT)` truncates weights without redistribution;
  this is existing portfolio behavior and outside this audit's authority.
- Validators commonly check numeric dtype but not `numpy.isfinite`, allowing
  infinity to pass several boundaries.
- Current 6A-3 output has zero eligible candidates. Connecting it today without
  fixing empty-path behavior would expose these failures immediately.

# 6. Migration Recommendation

## Target architecture

```text
results/production_candidates.csv
  -> new portfolio_candidate_adapter.py
       - validates candidate artifact provenance
       - selects Eligibility == ELIGIBLE only
       - preserves FinalScore, CandidateRank, TradeSignal,
         Confidence, RunId, AsOfDate, ScoreModelVersion
       - emits stable empty portfolio-input schema
       - joins only separately approved risk inputs
       - does not calculate weights, shares, or orders
  -> portfolio_risk.py
  -> position_sizing.py
  -> order_draft.py
  -> order_review.py
  -> portfolio action / daily decision reports
```

## New adapter required

`portfolio_candidate_adapter.py` should translate the validated production
candidate contract into a portfolio-input contract. It should:

1. require one RunId/AsOfDate/ScoreModelVersion;
2. reject stale, duplicate, malformed, mixed-version, and non-finite input;
3. filter only explicit `Eligibility == ELIGIBLE` rows;
4. verify eligible rows retain `TradeSignal == BUY`;
5. preserve CandidateRank rather than rerank on another score;
6. carry FinalScore under its truthful name;
7. emit a stable empty schema when zero candidates are eligible;
8. join a separately approved risk-input artifact by Ticker and matching
   provenance, or fail closed if required risk data is unavailable; and
9. never fabricate BacktestScore, historical returns, drawdown, Sharpe, risk
   level, fundamentals, price, or weights.

This second adapter is justified because `production_candidate_builder.py`
defines current signal eligibility, while the portfolio adapter defines the
input boundary and any approved risk-data join. Combining both would couple
production scoring artifacts to allocation policy.

## Modules requiring modification during implementation

| Module | Minimum migration change |
|---|---|
| `config.py` | Add production candidate/portfolio-input paths; retain legacy paths as research-only |
| `run_portfolio.py` | Run/validate the new portfolio candidate boundary before construction |
| `portfolio_risk.py` | Load new input, use CandidateRank/FinalScore, filter no eligibility itself, and handle empty/zero-risk inputs safely |
| `validate_portfolio_outputs.py` | Replace legacy performance schema; enforce finite values, provenance, eligibility lineage, and empty contract |
| `combined_scoring.py` | Remove BacktestScore dependency only after explicit fundamentals-policy approval |
| `validate_combined_outputs.py` | Match approved truthful score contract |
| `position_sizing.py` | Replace BacktestScore fields/fallback and use a synchronized positive finite price contract |
| `validate_position_sizing_outputs.py` | Handle empty input; enforce finite positive prices, integer non-negative shares, and configured exposure limits |
| `order_draft.py` | Carry provenance and ensure only eligible BUY lineage can produce Action=BUY |
| `validate_order_draft_outputs.py` | Enforce finite values, provenance, and stable empty schema |
| `order_review.py` | Fail closed on NaN/infinity/missing fundamentals and handle empty orders explicitly |
| `validate_order_review_outputs.py` | Validate empty/no-action state without row-zero indexing |
| `portfolio_action_report.py` | Replace BacktestScore label and report NO ORDERS truthfully |
| `daily_decision_report.py` | Verify and display RunId/AsOfDate/version compatibility |
| `report_terminal.py` / stock cards | Update portfolio field names and provenance display where consumed |

## Modules that should remain unchanged

- `score.py`;
- `trade_signal.py`;
- `production_candidate_builder.py` and its approved output semantics;
- indicator and canonical market-data logic;
- legacy `backtest_engine.py`, retained as explicitly research-only;
- production-faithful research backtest modules; and
- Investment Profile loaders and presentation behavior.

## Minimum implementation sequence

1. Approve the replacement portfolio risk-input/RiskLevel contract and the
   role of fundamentals. These cannot be inferred from candidate fields.
2. Implement and test `portfolio_candidate_adapter.py` in shadow mode.
3. Repair empty/non-finite/duplicate/missing-fundamental safety boundaries.
4. Migrate portfolio construction and validators from BacktestScore to
   FinalScore/CandidateRank with provenance.
5. Migrate sizing, orders, and reports without compatibility aliases.
6. Run legacy/new shadow comparison, then a clean zero-eligible end-to-end run.
7. Remove the legacy qualified file from production configuration only after
   human acceptance; retain it for research.

# 7. Release Blocker Assessment

| Finding | Severity | V3.8.1 blocker | Reason |
|---|---|---|---|
| Portfolio still consumes legacy technical-backtest candidates | High | YES | Production BUY semantics do not determine portfolio eligibility |
| Replacement RiskLevel/risk-input contract unresolved | High | YES for cutover | New candidates cannot safely drive existing weight multipliers |
| Zero eligible candidates not end-to-end safe | High | YES | Current real snapshot has zero eligible candidates |
| NaN order values can receive PASS | Critical | YES | Invalid orders can be presented as clean |
| All-Unknown creates NaN weights | High | YES | Allocation becomes invalid |
| Missing scores can receive weights | High | YES | Invalid candidate can enter allocation |
| Duplicate tickers consume holding slots | High | YES | Holding and exposure constraints can be distorted |
| Non-positive/infinite prices not rejected | High | YES | Share and value calculations can be invalid |
| Missing fundamentals can flow to BUY/PASS | High | YES | Missing data is treated as zero/fallback rather than degraded approval |
| Empty reports imply READY | High | YES | Runtime status is misleading on a valid no-action day |
| No RunId/AsOfDate propagation | High | YES | Stale/mixed artifacts can be combined |
| Legacy research fields remain in UI schemas | Medium | YES before cutover | Users could mistake legacy performance for production validation |
| Separate liquidity/volatility factors absent | Low | NO | Not required by existing policy; adding them would be new strategy work |

Conclusion: the adapter contract is ready for a separately approved portfolio
migration, but V3.8.1 is not ready to connect it directly. The smallest safe
path is a portfolio-input adapter plus boundary corrections and truthful schema
migration—not a filename swap or FinalScore-to-BacktestScore alias.
