# AI_investing V3.8.1 R1 — Report Truthfulness & Artifact Consistency

## 1. Problem

`report_terminal.py` declared `PIPELINE_STATUS = "PASS"` independently of its
inputs. It also displayed research rankings, legacy model portfolio rows, old
order review rows, and combined scores at one apparent authority level. A
missing, stale, mixed-run, or metadata-free artifact could therefore look like
a current production result. The runtime files observed at the R1 audit
confirmed the risk: legacy Portfolio and Order artifacts lacked the production
identity fields and could not be proven current.

## 2. Required Artifact Contract

The minimal production root is `results/production_candidates.csv`. If it is
empty or contains no `BUY` plus `ELIGIBLE` row, the legitimate result is
`NO_ACTION`; downstream action artifacts are not required.

When an actionable candidate exists, these artifacts are required:

1. Production Candidate — `results/production_candidates.csv`
2. Portfolio Risk — `results/portfolio_risk_inputs.csv`
3. Model Portfolio — `results/model_portfolio.csv`
4. Position Sizing — `results/model_portfolio_sizing.csv`
5. Order Draft — `results/order_draft.csv`
6. Order Review — `results/order_review.csv`

Top opportunities, combined score displays, company profiles, and research
cards are optional display enrichment. Their absence does not fail the
production report. They remain labeled research/optional.

## 3. Metadata Contract

- **RunId:** each required artifact must have one nonblank value and all
  required artifacts must match. Mixed values are `INCOMPATIBLE`.
- **AsOfDate:** one valid value is required. Cross-artifact mismatch is
  `STALE`; the existing production-candidate staleness allowance is reused for
  cross-day age checks.
- **UniverseVersion:** Production Candidate must match
  `config.PRIMARY_UNIVERSE_VERSION`. Missing is `UNKNOWN`; mismatch is
  `INCOMPATIBLE`. No second authority is introduced.
- **ScoreModelVersion:** one nonblank consistent version is required throughout
  every applicable production artifact. Missing is `UNKNOWN`; mismatch is
  `INCOMPATIBLE`.
- **RiskModelVersion:** required from Portfolio Risk through Order Review.
  Missing is `UNKNOWN`; mismatch is `INCOMPATIBLE`.

R1 never repairs, fills, or invents metadata. Empty candidate CSVs are the one
explicit identity exception because their stable schema represents a valid
zero-candidate production outcome and contains no rows on which to repeat
run-level values.

## 4. Status Semantics

- **PASS:** every conditionally required production artifact exists, validates,
  has complete compatible metadata, is current, and has no required failure.
- **FAILED:** a required artifact contains an explicit validation or blocking
  failure.
- **INCOMPATIBLE:** versions, RunId, future date, or other identity evidence
  conflicts.
- **STALE:** AsOfDate is beyond the existing candidate staleness window or
  required artifacts disagree on AsOfDate.
- **UNKNOWN:** current-run identity cannot be proven because a required artifact
  or metadata value is absent, blank, unreadable, or mixed without a stronger
  conflict classification.
- **NO_ACTION:** a valid production candidate stage has no actionable candidate
  or is header-only. This is not failure and never authorizes legacy fallback.

## 5. Aggregate Precedence

`FAILED > INCOMPATIBLE > STALE > UNKNOWN > NO_ACTION > PASS`

This ordering is deterministic. A valid candidate plus stale portfolio is
`STALE`; missing metadata is `UNKNOWN`; all-valid zero-action evidence is
`NO_ACTION`.

## 6. Legacy / Research Boundary

Backtest artifacts remain `RESEARCH_ONLY`. The current-report reader has no
backtest path and never searches historical archives. Research opportunities
and combined-score enrichment are labeled separately from production evidence.
Unverifiable Portfolio and Order tables are explicitly marked
`UNVERIFIED, NOT CURRENT PRODUCTION`.

## 7. Runtime Enforcement

- `report_artifact_consistency.py` reads only fixed current production paths and
  evaluates conditional requirements, minimum report schema, validation
  evidence, freshness, and metadata consistency.
- `report_terminal.py` derives Report Status from that assessment, displays all
  five metadata fields and evidence issues, and no longer contains a PASS
  constant.
- `portfolio_action_report.py` displays the same evidence-derived status and
  metadata. Unverified artifact content cannot produce a ready decision.
- `daily_decision_report.py` labels its context as current, its technical input
  as `RESEARCH_ONLY`, and its action section as evidence-validated.
- Missing optional display inputs render empty sections rather than failing the
  production consistency assessment.

## 8. Remaining Optional / Deferred Items

R1 does not retrofit metadata into generated Portfolio/Order artifacts, rewrite
historical files, or build a manifest. Existing legacy runtime artifacts will
truthfully remain `UNKNOWN` until a later governed generation path emits full
metadata. Historical shadow archives retain their existing immutable research
contract; R1 adds only the reusable label `HISTORICAL ARCHIVED REPORT — NOT
CURRENT` and does not restructure the archive system.
