## 2. Market Data Root Cause

The production download uses `yfinance.download(... interval="1d",
auto_adjust=False)`. At 2026-08-13 12:00 New York time, a read-only diagnostic
returned a 2026-08-13 daily row for all five affected names while the regular
session was still open. Raw source values already violated completed-bar OHLC
relationships:

| SPIR | 13.1650 | 14.6608 | 13.2500 | 13.8250 | 319,817 |

The values matched the saved current-day rows apart from normal live-price
movement and CSV floating precision. The defect therefore originated upstream
as a partial daily bar, not in MultiIndex flattening, serialization, loading, or
validator normalization.

## 3. Market Data Fix

`market_session.py` defines a minimal New York completed-session boundary. Before
canonical save, `update_data.py` excludes a row dated as the current New York
session until 16:15 ET. The 15-minute buffer prevents a just-closed, still
settling bar from immediately becoming canonical. Historical rows are untouched;
after the completion boundary the row becomes eligible normally.

No ticker exception exists. OHLC rules in `stock_loader.py` and
`data_readiness.py` remain unchanged and still fail invalid completed bars.
Universe membership remains unchanged. The conservative weekday calculation
does not add a large exchange-calendar dependency; on a holiday it can only
delay a nonexistent current-session row, not admit a partial bar.

## 5. Run Identity Root Cause

`run_all.py` previously created only a log filename at startup. Candidate RunId
was created much later, so an upstream failure had no report-visible identity.
Readers evaluated current fixed paths and AsOfDate; a prior success from the same
calendar day therefore remained indistinguishable from the later failed attempt.

## 6. Run Identity Fix

`results/current_run_status.json` is a lightweight runtime-only authority record.
At pipeline start it records CurrentRunId, StartTime, intended completed-session
AsOfDate, RUNNING status, and update time. On failure it records FAILED,
FailedStage, and reason; current portfolio/daily report paths are replaced with
explicit failure evidence. On success the context closes with the fresh
candidate RunId and AsOfDate.

`assess_current_report()` gives latest-attempt failure precedence over artifacts.
For a successful context, both RunId and AsOfDate must match the report artifact;
mismatch becomes INCOMPATIBLE or STALE. Old artifacts remain on disk as prior
evidence, and no legacy backtest fallback is used.

## 7. Same-Day Multi-Run Test

The deterministic test creates Run A as successful NO_ACTION, then Run B on the
same AsOfDate as an upstream failure. Current assessment becomes FAILED with Run
B identity; Run A is not shown as current. Additional tests cover prior-day
artifacts, successful RunId mismatch, no backtest fallback, explicit failure
report output, and valid latest NO_ACTION.
