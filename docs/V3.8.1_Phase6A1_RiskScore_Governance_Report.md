# AI_investing V3.8.1 Phase 6A-1 RiskScore Governance Report

Analysis date: 2026-08-12

## 1. Problem Statement

The prior technical score assigned `RiskScore = 50` to every eligible symbol.
Although this could not distinguish securities or change same-date rank order,
its 15% RawScore weight added 7.5 RawScore points and therefore 5.25 FinalScore
points to every observation. It changed the absolute meaning of the unchanged
BUY and WATCH thresholds without contributing information.

## 2. Before/After Formula

Before:

```text
RawScore =
    TrendScore × 0.40
  + MomentumScore × 0.25
  + VolumeScore × 0.20
  + RiskScore × 0.15

RiskScore = 50
```

After:

```text
RawScore =
    TrendScore × 0.40
  + MomentumScore × 0.25
  + VolumeScore × 0.20
```

The existing FinalScore structure is unchanged:

```text
FinalScore = RawScore × 0.70 + RS_Score × 0.20 + NearHighScore × 0.10
```

No remaining weights were renormalized. `RiskScore` remains available as a
zero-valued diagnostic placeholder, but it has no active formula influence.

## 3. Implementation Changes

- Removed the constant RiskScore term from `calculate_rank_score_diagnostics()`.
- Added deterministic metadata:
  `ScoreModelVersion = technical-score-v3.8.1-r1`.
- Added ScoreModelVersion to ranking and score-diagnostic output rows.
- Preserved TrendScore, MomentumScore, VolumeScore, RS_Score, NearHighScore,
  Confidence, and FinalScore component logic.
- Added a reproducible old/new comparison artifact at
  `results/score_model_v3.8.1_r1_impact.csv`.
- Regenerated `results/score_diagnostics.csv` and
  `results/score_threshold_analysis.csv` using canonical local OHLCV.

Downstream score consumers remain `rank_stocks_v2.py`, `trade_signal.py`, the
Phase 4 threshold diagnostic, and the Phase 5 production-faithful research
path. No consumer threshold or trading rule was changed.

## 4. Score Impact Analysis

The historical comparison contains 4,604 eligible date-symbol observations
from the current 19-symbol research universe.

| Measure | Old FinalScore | New FinalScore | Shift |
|---|---:|---:|---:|
| Average | 38.786507 | 33.536507 | -5.250000 |
| Minimum | 1.385368 | -3.864632 | -5.250000 |
| Maximum | 90.323013 | 85.073013 | -5.250000 |
| Standard deviation | 18.834440 | 18.834440 | unchanged |

- Minimum shift: -5.25.
- Maximum shift: -5.25.
- Average shift: -5.25.
- Same-date rank-order changes: 0 of 4,604 observations.

The unchanged dispersion and rank order confirm that the correction removes
only the non-informative intercept. It does not add a factor or optimize the
model.

## 5. Threshold Impact Analysis

BUY remains `FinalScore >= 75`; WATCH remains `FinalScore >= 60`. Applying the
unchanged thresholds mechanically produces:

| Classification | Old threshold-only count | New threshold-only count |
|---|---:|---:|
| BUY | 109 | 40 |
| WATCH | 571 | 379 |
| IGNORE | 3,924 | 4,185 |

Applying the complete unchanged production signal policy, including volume,
near-high, Close/MA20, and MA20/MA60 filters, produces:

| Production classification | Old count | New count |
|---|---:|---:|
| BUY | 91 | 34 |
| WATCH | 589 | 385 |
| IGNORE | 3,924 | 4,185 |

These changes are the expected mechanical consequence of removing 5.25
non-informative FinalScore points. They are not evidence for changing either
threshold, and this phase makes no threshold recommendation.

## 7. Architecture Boundary Confirmation

The RiskScore correction does not modify:

- portfolio construction;
- position sizing;
- order review;
- execution or portfolio simulation;
- legacy or production-faithful backtest modules;
- BUY/WATCH thresholds or signal filters; or
- the Investment Profile layer.

Only scoring implementation, score-related diagnostics/tests, and this report
are changed.

## 8. Remaining Questions

- Threshold suitability under the corrected absolute score scale remains a
  separate governance review; this report does not propose a threshold change.
- A future informative risk factor would require its own definition, data
  contract, model-version increment, and validation. None is introduced here.
- ScoreModelVersion is intentionally minimal metadata. Cross-artifact RunId and
  AsOfDate enforcement remain outside Phase 6A-1.
