# AI_investing V3.8.1 Phase 6B-2 Portfolio Candidate Adapter Report

Implementation date: 2026-08-12

## 1. Problem Statement

The production scoring pipeline now emits a validated candidate contract, but
the portfolio pipeline still consumes legacy technical-backtest qualification.
A safety boundary is required before any future portfolio migration so invalid,
ineligible, duplicate, mixed-run, or non-finite candidates cannot enter
portfolio construction.

## 2. Previous Architecture

```text
backtest_engine.py
  -> results/backtest_qualified_20d.csv
  -> portfolio_risk.py
  -> position sizing and orders
```

`results/production_candidates.csv` previously had no portfolio-facing
validation layer.

## 3. New Adapter Architecture

```text
results/production_candidates.csv
  -> portfolio_candidate_adapter.py
       - validates identity and score metadata
       - preserves production score/signal/eligibility
       - applies BUY + ELIGIBLE safety gate
       - records unresolved risk-input status
  -> results/validated_portfolio_candidates.csv
```

This is an isolated boundary. It does not calculate weights, risk levels,
shares, orders, performance, Sharpe, or drawdown.

## 4. Candidate Contract

Output fields:

- Identity: `Ticker`, `AsOfDate`, `RunId`, `ScoreModelVersion`.
- Candidate information: `CandidateRank`, `FinalScore`, `TradeSignal`,
  `Eligibility`.
- Boundary result: `PortfolioEligible`, `ValidationStatus`,
  `ValidationReason`.

Only `TradeSignal=BUY` together with `Eligibility=ELIGIBLE` sets
`PortfolioEligible=True`. Because no approved portfolio risk inputs exist, an
accepted row explicitly carries `ValidationStatus=RISK_INPUT_PENDING`.
No risk fields or fake values are created.

WATCH and IGNORE rows remain in the artifact for auditability, with
`PortfolioEligible=False` and `ValidationStatus=NOT_PORTFOLIO_ELIGIBLE`.

## 5. Validation Rules

The complete artifact is rejected for:

- missing required columns or identity values;
- normalized duplicate tickers;
- mixed RunId, AsOfDate, or ScoreModelVersion;
- invalid AsOfDate;
- missing, NaN, or infinite FinalScore;
- invalid, duplicate, non-positive, or non-integer CandidateRank;
- signal outside BUY/WATCH/IGNORE; or
- eligibility outside ELIGIBLE/INELIGIBLE.

An empty input DataFrame with the required source schema produces a stable,
header-only output. Zero portfolio-eligible rows does not crash and does not
promote any candidate.

## 6. Safety Improvements

- Production eligibility is enforced explicitly rather than assumed from file
  membership.
- WATCH and IGNORE cannot cross the portfolio boundary as eligible.
- A BUY row whose source Eligibility is INELIGIBLE cannot cross the boundary.
- Duplicate ticker and mixed-run artifacts fail closed.
- NaN and infinity cannot enter the validated score contract.
- Risk-input absence is visible as `RISK_INPUT_PENDING` instead of fabricated
  MaxDrawdown, SharpeRatio, RiskLevel, or multiplier values.
- Input CSV files are read-only; output uses a separate fixed-schema artifact.

## 7. Remaining Migration Work

**This adapter does not replace `portfolio_risk.py` yet.**

The following work remains separately governed:

1. Define an approved portfolio risk-input and RiskLevel contract.
2. Make `portfolio_risk.py` consume validated candidates and handle zero
   eligible/pending-risk rows safely.
3. Remove BacktestScore and legacy performance fields from production
   portfolio, validator, sizing, order, and report schemas.
4. Decide how fundamentals interact with FinalScore; do not silently reuse the
   legacy BacktestScore formula.
5. Propagate RunId, AsOfDate, and ScoreModelVersion through sizing, orders, and
   reports.
6. Repair empty-order, non-finite price/order, duplicate, and missing-
   fundamental boundaries before cutover.
7. Retain the legacy backtest as research-only.

No score, threshold, portfolio, position-sizing, order-review, reporting, or
version behavior was changed in Phase 6B-2.
