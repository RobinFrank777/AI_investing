# AI_investing V3.8.2 P2.4.2 Provider-Rejected Symbol Quarantine Report

## Current global readiness behavior

Before P2.4.2, `run_all.validate_market_data` converted any stale warning into a
global failure. Insufficient-history symbols were the only explicit non-blocking
exclusion. This was historical orchestration behavior, not a documented safety
requirement of the scoring model. More importantly, `run_ranking_pipeline`
selected `IsValid` symbols from the legacy validator; a stale symbol could remain
`IsValid=True`, so merely removing the global failure would have been unsafe.

The global failure trigger was therefore `run_all.py`, while the unsafe inclusion
boundary was the ranking entry in `rank_stocks_v2.py`.

## Why provider-rejected differs from canonical corruption

A provider-rejected row is rejected before publication and the previous valid
canonical history remains unchanged. It is unavailable for the required session,
but it does not prove local storage corruption. `INVALID_CANONICAL_DATA` means the
stored canonical file itself violates schema, numeric, duplicate-date, or OHLC
rules and remains a hard global failure. The OHLC invariant was not relaxed.

## Per-symbol readiness contract

The canonical authority remains `results/universe150_data_quality.csv` and uses:

- `READY`: valid OHLCV, sufficient history, latest accepted date equals the
  required completed session.
- `INSUFFICIENT_HISTORY`: canonical data is valid but history is below the
  existing minimum.
- `PROVIDER_REJECTED`: the current refresh contained an invalid provider row;
  the symbol is quarantined even if an older/same-date accepted row exists.
- `STALE_MARKET_DATA`: latest accepted canonical date is behind the required
  session.
- `INVALID_CANONICAL_DATA`: local canonical storage is invalid; global failure.

If at least one READY symbol exists, research may continue on exactly the READY
subset. If none exists, the pipeline fails. No new percentage safety floor was
invented.

## Cross-sectional score safety

Readiness filtering now occurs before `rank_stocks`. `RS_Score`, percentile
ranks, signals, and every other score are recomputed from only the current READY
population. `NearHighScore` remains an individual current-history calculation.
No previous score artifact is loaded or merged. A captured stale high-score
fixture proves that a quarantined symbol never reaches the ranking function.

The production candidate builder consumes the freshly generated rank artifact
and continues to enforce a uniform `MarketDataDate`; portfolio, sizing, and order
stages consume only the resulting candidate chain.

## AsOfDate semantics

The required session is provided by the existing completed-session contract.
Every READY symbol must match that session. A prior-day row is recorded as stale,
is not scored, and cannot lower or masquerade as the run AsOfDate.

## UniverseVersion semantics

`UniverseVersion` remains `config.PRIMARY_UNIVERSE_VERSION`, representing the
full configured Universe150. The READY subset does not receive a synthetic
UniverseVersion. Configured and actual research population counts are disclosed
through the canonical readiness artifact and reports.

## Exclusion artifact

`results/universe150_data_quality.csv` is the sole exclusion authority. It records
`Ticker`, `Status`, `Reason`, `LatestAcceptedDate`, `RequiredAsOfDate`, and
`ProviderRejectedDate`, plus the existing validation details and full
`UniverseVersion`. Both validation and ranking rebuild this artifact; ranking
selects only rows whose `Ready` value is true.

## Report disclosure

The daily technical report, portfolio action report, daily decision report, and
terminal disclose configured, research-ready, excluded, provider-rejected, and
insufficient-history counts. Exclusion symbols and reasons are shown in the text
reports. Overall status retains the existing `PASS` / `NO_ACTION` vocabulary and
uses `Data Coverage: PARTIAL`; it never claims full readiness when exclusions
exist.

## Selected production decision

**PARTIAL-READINESS CONTINUATION** — implemented as per-symbol fail-closed
quarantine with explicit disclosure. The model safely recomputes its
cross-sectional values over the current READY population, and downstream stages
cannot receive an excluded ticker through the formal run path.
