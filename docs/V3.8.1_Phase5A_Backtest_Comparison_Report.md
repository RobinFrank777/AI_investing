# AI_investing V3.8.1 Phase 5A Backtest Comparison Report

Comparison date: 2026-08-12

## Executive result

The new module faithfully reproduces the current production score and signal
policy historically. Its results differ materially from the legacy backtest
because the legacy engine tests technical-filter transitions without FinalScore,
whereas production requires FinalScore ≥ 75 plus those filters.

## Results

### Production-faithful backtest

- Eligible history: 4,604 date-symbol observations across 249 dates.
- Output signal observations: 680.
- BUY observations: 91 across 64 dates and 7 tickers.
- WATCH observations: 589.
- Valid BUY returns: 89 at 5D, 87 at 20D, 66 at 60D.
- Average forward return: 1.83% (5D), 10.95% (20D), 25.34% (60D).
- 20D win rate: 66.67%.
- 20D return volatility: 23.54%.
- 20D annualized Sharpe estimate: 1.65.
- Diagnostic maximum drawdown proxy: -7.24%.

The drawdown proxy compounds daily-equivalent returns derived from each signal
date’s mean 20D BUY cohort. It is not executable portfolio drawdown because
signals and holding windows overlap and no sizing/capital constraint exists.

### Legacy backtest

- BUY days: 956.
- non-BUY→BUY entries: 272.
- completed fixed-20-day trades: 255.
- average completed-trade return: 5.37%.
- completed-trade win rate: 59.22%.
- completed-trade return volatility: 18.22%.

The legacy summary is an entry-transition/fixed-holding simulation. Its pooled
trade figures are not directly comparable to production signal-day observations.

## Method comparison

| Dimension | Legacy backtest | Production-faithful backtest |
| --- | --- | --- |
| Canonical loader | YES | YES |
| Production indicators | YES | YES |
| Component scores | NO | YES |
| Date-local RSScore | NO | YES |
| FinalScore | NO | YES |
| Production signal function | NO | YES |
| BUY threshold ≥ 75 | NO | YES |
| Four technical BUY filters | YES | YES |
| Signal count unit | BUY days / entry transitions | BUY/WATCH date-symbol observations |
| Return evaluation | non-overlapping per-symbol 20-row entries | 5D/20D/60D forward return per signal observation |

## Why results differ

1. The FinalScore gate removes most technical-filter BUY days. Production
   generated 91 BUY observations versus 956 legacy BUY days over the available
   histories.
2. Legacy entries collapse consecutive BUY days into one entry; production
   emits a screening classification every day.
3. Production FinalScore depends on same-date cross-sectional RS percentile,
   which cannot be reproduced ticker-by-ticker.
4. The eligible windows differ: faithful scoring needs enough history for
   MA/High252 plus 60-day return and date-local peers; the legacy engine can
   classify rows under its own availability rules.
5. Return aggregation differs. Production-faithful output retains overlapping
   signal horizons, while legacy trades use first-entry transitions and a fixed
   20-row exit.

## Consistency assessment

Signal consistency with production is **PASS**:

- score components call current production scoring code;
- FinalScore calls the current production formula;
- signals call the actual production `generate_signals()` function;
- fixed tests confirm BUY/WATCH output matches production policy; and
- no threshold, filter, score, or weight is duplicated with a changed value.

Look-ahead control is **PASS for price/score computation**. Tests prove future
price mutations do not change earlier scores/signals. Point-in-time universe
membership remains unavailable, so survivorship/selection bias is an explicit
limitation rather than a hidden claim.

## Recommendation

Use `production_backtest.py` as the diagnostic baseline for current production
signal behavior, not the legacy backtest. Do not yet use its headline returns
to optimize thresholds: first define whether repeated daily BUY observations
or transition entries are the intended economic unit, add point-in-time
universe membership where possible, and implement portfolio-realistic exposure,
costs, and non-overlapping/out-of-sample validation in a separately approved
phase.

The prudent interpretation is evidence of code-path consistency, not proof of
future profitability.
