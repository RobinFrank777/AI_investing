# V3.8.1 C1 Production Capital Flow Contract Report

## 1. Objective

C1 is a correctness regression for the production capital chain. It verifies that already-defined P1/O1/O1.1 safety contracts compose without changing investment policy, allocation rules, or order rules.

## 2. Tested Flow

```text
Qualified Candidate Fixture
→ portfolio_risk.build_model_portfolio
→ position_sizing.add_target_dollar_amount / add_share_sizing
→ order_draft.build_order_draft
→ order_review.build_order_review
```

Tests call the real production functions with deterministic tickers, risk inputs, prices, fundamentals, and capital. They use no network or runtime market files.

The executable `run_portfolio.py` path currently enriches the portfolio with combined/fundamental data between portfolio risk and position sizing. The fixture models that established enrichment explicitly. The metadata-rich candidate/risk calculator path remains a separate generation and is not unified during C1.

## 3. Capital Invariants

- Allocated positions ≤ `MAX_HOLDINGS = 10`.
- Every TargetWeight is finite, non-negative, and ≤ 10%.
- Total TargetWeight ≤ 80%; under-investment is valid.
- `TargetDollarAmount = PortfolioCapital × TargetWeight`, within currency rounding.
- TargetShares are non-negative whole integers.
- Drafts contain only positive whole shares and finite positive prices/values.
- `TotalDraftValue ≤ AllocatedPortfolioValue ≤ PortfolioCapital`.
- `RemainingCash = PortfolioCapital - TotalDraftValue ≥ 0` within one-cent tolerance.
- Integer-share truncation may make DraftValue lower than TargetValue; that difference is residual cash and is not redistributed.

The deterministic three-position reconciliation uses $100,000 capital and unequal prices. Total exposure is 30%, allocated value is $30,000, draft value remains below that amount, and residual cash remains positive. It proves no forced 80% deployment.

## 4. No-Action Contract

```text
0 qualified candidates
→ empty portfolio / NO_QUALIFIED_CANDIDATES
→ empty header-stable sizing
→ empty draft / NO_DRAFT_ORDERS
→ empty review / NO_ORDERS_TO_REVIEW
→ PortfolioReviewFlag NOT_APPLICABLE
```

All-Unknown, all-invalid, and all-zero-multiplier candidate sets also terminate safely without orders.

## 5. Numeric Safety

- NaN/±Inf BacktestScore and risk inputs cannot enter allocation.
- NaN, negative, or non-finite TargetWeight cannot produce ready sizing.
- Zero/negative/NaN/±Inf prices produce INVALID_PRICE and no draft.
- Zero or insufficient capital leads to zero shares and no draft; invalid capital raises a clear validation error.
- Injected negative, zero, fractional, NaN, or Inf shares cannot become draft orders.
- Invalid allocated/order values cannot become draft orders or PASS review.

## 6. Review Propagation

- Missing fundamentals produces row `REVIEW` and aggregate `REVIEW_REQUIRED`.
- Any blocked numeric/order row produces aggregate `BLOCKED`.
- `BLOCKED > REVIEW_REQUIRED > PASS`; empty is `NOT_APPLICABLE`.
- PASS means only mechanical checks passed. Human decision remains mandatory.

## 7. Cash Reconciliation

The tests calculate, without adding production fields:

```text
AllocatedPortfolioValue = sum(TargetDollarAmount)
TotalDraftValue = sum(EstimatedOrderValue)
RemainingCash = PortfolioCapital - TotalDraftValue
```

Assertions require `TotalDraftValue ≤ AllocatedPortfolioValue ≤ PortfolioCapital` and non-negative RemainingCash within $0.01 tolerance. Per-position whole-share truncation is also verified to leave, never consume, residual cash.
