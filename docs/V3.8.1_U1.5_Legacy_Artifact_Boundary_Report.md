# V3.8.1 U1.5 Legacy Artifact Boundary Report

## 1. Problem

The former production watchlist contained 19 stocks, while the current authoritative universe contains 150. Cross-sectional fields such as `RS_Score`, technical rank, the cross-sectional component of `FinalScore`, candidate rank, portfolio input rank, and backtest qualification depend on the comparison set. Results calculated at N=19 and N=150 therefore do not share the same semantics and must not be compared or consumed as though they do.

Existing artifacts generally have no Universe identity. Their filenames and dates do not prove which membership set generated them.

## 2. Current Universe Authority

The sole Primary Universe is `data/AI_investing_universe_150_V2.csv`. The sole authoritative identity value is `config.PRIMARY_UNIVERSE_VERSION`, currently `AI_investing_universe_150_V2`.

## 3. UniverseVersion Contract

The metadata field is always named `UniverseVersion`.

- **MATCH**: a non-empty artifact value exactly equals `PRIMARY_UNIVERSE_VERSION`. It may be recognized as using the current Universe contract.
- **MISMATCH**: an explicit artifact value differs from the current value, or a tabular artifact contains mixed explicit values. It is incompatible/stale.
- **MISSING / LEGACY**: the field or value is absent/blank. It is unverifiable and must never be inferred to be current.

`universe_metadata.py` implements these classifications and current-producer tagging. It imports the value from `config.py`; it does not define another version setting.

## 5. Producer Tagging Implemented

- `rank_stocks_v2.rank_stocks`: tags the returned ranking DataFrame. Consequently newly written `results/stock_rank.csv` and `results/top10.csv` declare the current version.
- `combined_scoring.calculate_combined_score`: tags newly calculated combined-score output.
- `production_candidate_builder`: requires a MATCH rank input and propagates its `UniverseVersion` into newly produced candidates. This reuses the reader's existing metadata validation boundary.

Tagging adds one metadata column only. It does not change ticker membership, scores, ordering, or trade signals.

## 6. Reader Enforcement Deferred

U1.5 does not implement broad runtime enforcement. R1 must add coherent checks at these formal boundaries:

- backtest qualification and model portfolio readers;
- combined-score inputs;
- portfolio candidate adapter and portfolio snapshot/risk readers;
- order draft/review inputs;
- daily and terminal report inputs;
- archived report and historical shadow inputs.

Those checks should jointly validate `UniverseVersion`, `RunId`, `AsOfDate`, `ScoreModelVersion`, and `RiskModelVersion` where applicable. `report_terminal.py` and the portfolio/order pipelines were intentionally not rewritten here.

## 7. Historical Artifact Policy

Historical artifacts are retained in place. They are not deleted, moved, bulk rewritten, or assigned the current version. Missing metadata remains LEGACY / UNVERIFIABLE; an explicit different version is INCOMPATIBLE / STALE. Neither may be used as a current production input without an explicit future compatibility decision.

## 8. Scope Verification

U1.5 does not modify the score model, momentum formula, `FinalScore` formula, BUY/WATCH thresholds, portfolio investment logic, order logic, Investment Profile, or runtime `PROJECT_VERSION`. No historical CSV or report artifact is rewritten.
