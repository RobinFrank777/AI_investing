# AI_investing V3.8.1 G1 — Generated Artifact Governance

## 1. Problem

Runtime ranking, chart, and report writers historically produced files in
`results/`, `reports/`, `charts/`, and the repository root. Although most new
outputs were already ignored, 14 generated charts, two generated HTML reports,
and one legacy root ranking CSV remained tracked. Running their writers could
therefore modify the source working tree even though the files were
reproducible runtime output rather than source authority.

## 2. Governance Contract

Git tracks:

- Python source and configuration;
- tests and their explicit fixtures;
- documentation;
- templates and static source assets;
- canonical user-maintained inputs and required examples; and
- intentionally governed historical evidence when explicitly designated.

Git ignores:

- `results/` runtime results and diagnostics;
- generated daily, decision, terminal, and legacy HTML reports;
- generated research cards;
- local logs;
- generated ranking, candidate, portfolio, sizing, order, and backtest output;
- generated chart files; and
- specific legacy root analysis outputs retained for compatibility.

Ignore rules control versioning only. They do not delete local artifacts or
prevent pipeline readers and writers from using them.

## 6. Runtime Output Locations

- `results/`: production/research rankings, candidates, risk inputs,
  portfolios, sizing, orders, backtests, diagnostics, and generated dashboards;
- `reports/`: daily reports, decision reports, terminal HTML, cards, and legacy
  HTML reports;
- `logs/`: pipeline and research execution logs;
- `charts/`: legacy and practice-generated PNG charts;
- repository root: specific compatibility outputs from legacy analysis scripts.

All current production writers using `config.py` continue to target their
existing `results/` or `reports/` paths. Directory creation remains owned by
the existing writers; G1 does not change that runtime contract.

## 7. Deferred Path Cleanup

The following remain V3.9 architecture candidates rather than G1 migrations:

- `rank_stocks.py` writing root `stock_rank.csv`;
- `analyze_stock.py` writing root `summary.csv`;
- practice Sharpe/risk CSV writers using the project root;
- legacy chart writers using `charts/`; and
- legacy HTML writers using `reports/`.

Moving them now would require coordinating downstream consumers and practice
scripts. Specific ignore rules provide the required source/runtime separation
without a risky directory refactor.

## 8. Validation

Governance validation uses `git check-ignore -v` on representative result,
diagnostic, report, chart, and legacy root outputs. Negative checks verify that
the Primary Universe, examples, template, and documentation remain visible to
Git. The full unit suite, Python compilation where applicable, and
`git diff --check` provide regression and formatting verification.
