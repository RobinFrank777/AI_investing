# V3.8.1 O1 Order Chain Hardening Report

## 1. Objective

O1 hardens `position_sizing.py → order_draft.py → order_review.py` so empty, invalid-price, non-finite, zero-share, and missing-fundamental states remain safe and explicit. No broker execution is introduced.

## 2. Previous Risks

- LatestClose accepted Inf and non-positive values.
- Sizing divided before validating price and cast unsafe results directly to integer.
- Empty/no-size results lacked stable status and schema guarantees.
- Draft filtering only checked shares greater than zero; other numeric fields were not validated together.
- Review comparisons allowed NaN to bypass conditions and potentially PASS.
- Missing fundamentals could PASS.
- Empty review output later crashed on `iloc[0]`.

## 3. Position Sizing Contract

TargetWeight and capital must be finite and non-negative. `TargetDollarAmount = capital × TargetWeight`. LatestClose must be finite and strictly positive. Whole shares retain the existing non-negative integer truncation policy; no fractional shares or residual-cash optimizer is added. Zero shares produce `NO_SIZABLE_POSITION`, not an exception or order.

Actual states: `POSITION_READY`, `NO_SIZABLE_POSITION`, `INVALID_PRICE`, `INVALID_SIZING_INPUT`.

## 4. Order Draft Contract

A draft requires complete schema, a positive integral TargetShares value, finite positive LatestClose, finite non-negative allocated value, and—when present—`SizingStatus=POSITION_READY`. Invalid rows are excluded. Empty output retains the established `ORDER_COLUMNS` schema and status `NO_DRAFT_ORDERS`; normal output has `DRAFT_READY`.

## 5. Order Review Contract

Empty schema-preserving orders return `NO_ORDERS_TO_REVIEW` with portfolio flag `NOT_APPLICABLE`. NaN/Inf or non-positive shares, price, or estimated value are `BLOCKED`. Missing/blank/`MISSING` FundamentalRating is `REVIEW`. Existing high-risk and value-limit review rules remain.

`PASS` means mechanical contract checks passed and the proposal may proceed to human review. It is never automatic execution authorization.

## 6. Stable Status Contract

- Position sizing: `POSITION_READY`, `NO_SIZABLE_POSITION`, `INVALID_PRICE`, `INVALID_SIZING_INPUT`
- Order draft: `DRAFT_READY`, `NO_DRAFT_ORDERS`
- Order review: `REVIEW_COMPLETE`, `NO_ORDERS_TO_REVIEW`; row statuses remain `PASS`, `REVIEW`, `BLOCKED`

## 7. Downstream Compatibility

Existing sizing, draft, and review columns are preserved. Empty outputs are header-stable, so report/validator readers can inspect them without guessing a schema. The print review path no longer indexes the first row when empty.

Real-artifact read-only smoke check: 10 portfolio inputs produced 10 sizing rows, 10 draft rows, and 10 reviewed rows; review completed with portfolio flag PASS and row statuses 5 PASS / 5 REVIEW. No artifacts were overwritten and no order was transmitted.
