# AI_investing V3.8.1 Phase 4 Production/Backtest Alignment Audit

Audit date: 2026-08-12

## Executive finding

**Production and backtest signal definitions are not aligned.** They share the
canonical loader, indicators, and four technical BUY filters, but the active
backtest does not calculate Score, RS_Score, NearHighScore, or FinalScore and
does not enforce the production FinalScore threshold.

## Side-by-side behavior

| Dimension | Production ranking | Active backtest | Aligned? |
| --- | --- | --- | --- |
| Entry point | `rank_stocks_v2.py` | `backtest_engine.py` | N/A |
| Data loader | `stock_loader.load_stock()` | `stock_loader.load_stock()` | YES |
| OHLCV contract | canonical named OHLCV | canonical named OHLCV | YES |
| Indicators | `calculate_indicators()` | `calculate_indicators()` | YES |
| Raw score | current weighted technical score | not calculated | NO |
| RSScore | same-run cross-sectional percentile | not calculated | NO |
| FinalScore | calculated | not calculated | NO |
| WATCH | FinalScore ≥ 60 | indicators/data available | NO |
| BUY score gate | FinalScore ≥ 75 | none | NO |
| BUY technical gates | Volume > 0.8, near high, Close > MA20, MA20 > MA60 | same four gates | YES |
| Signal date | latest row in ranking run | each historical row | intentionally different |
| Entry event | current screening state | transition into BUY from non-BUY | intentionally different |
| Holding rule | none in ranking | fixed 20 trading rows | N/A |

## Date and return logic

- Both paths calculate indicators from information at or before the signal row.
- Production trailing returns use `Close[-1]/Close[-20]-1` and
  `Close[-1]/Close[-60]-1`, corresponding to 19 and 59 row intervals.
- The existing backtest does not consume those returns for signal generation.
- Backtest forward returns use shifts of 5, 20, and 60 rows after the signal
  date, which is appropriate for evaluation and unavailable to the signal.
- Backtest BUY entries are only non-BUY→BUY transitions, while Phase 4
  sensitivity counts every date-symbol observation crossing a threshold. The
  two counts must not be compared as if they are identical concepts.

## Cross-sectional requirement

Production FinalScore contains `RS_Score`, a percentile calculated across the
symbols present on the scoring date. A faithful historical production-score
backtest therefore requires date-by-date cross-sectional scoring. Scoring one
ticker independently cannot reproduce production FinalScore.

The Phase 4 diagnostic performs this date-by-date reconstruction across the
current 19-symbol watchlist. It does not modify `backtest_engine.py` or claim to
be a replacement strategy backtest.

## Quantified consequence

Across 4,604 eligible historical date-symbol observations:

- `FinalScore >= 75`: 109 observations on 72 dates.
- Full production BUY policy at the same dates: 91 observations on 64 dates.

Thus, even after FinalScore is reconstructed, the additional BUY filters remove
18 threshold-qualified observations. The existing backtest applies those four
filters but omits the score gate, so its historical BUY population is a
different population.

## Integrity conclusion

The current backtest is internally consistent with its own documented
technical-filter strategy, but it is not a validation of the current production
FinalScore BUY policy. Historical backtest performance must not be cited as
evidence that the production score threshold of 75 is calibrated.

Recommendation: a future, separately approved correctness phase should define
one shared signal-policy function or an explicit versioned policy contract and
then rebuild the backtest baseline. Phase 4 does not make that change because it
would alter backtest logic and is expressly out of scope.
